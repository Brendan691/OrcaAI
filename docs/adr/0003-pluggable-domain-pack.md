# 3. 航运知识做成可插拔的领域包

- 状态:已接受
- 日期:2026-07-27

## 背景

项目新定位:不再是"针对航运新闻的知识管理工具",而是"**为航运知识管理优化过的通用知识管理工具**"。

这句话若只改文案、不改代码,答辩被问"通用体现在哪"会答不上。需要在架构上给它一个技术落点。

现状:航运的四维标签已经在 `config/tags.yaml` 里(半抽象),但"航运"字样散落在提示词、报告模板、关键词规则、类名注释里,和内核纠缠。

## 决策

引入**领域包(DomainPack)**概念,把一个行业的知识收拢到 `domains/<name>/` 目录:

```
domains/
  maritime/          # 航运领域包
    tags.yaml        # 四维标签体系
    prompts.py       # 分类提示词、问答系统提示词
    reports.py       # 周报/风险预警/公约解读模板
    keywords.py      # 规则引擎关键词(LLM 失败时的回退)
  example/           # 空模板,证明领域可替换
```

- **内核不认识"航运"**(见 CONTEXT.md 不变量 1)。内核只认 DomainPack 接口。
- 当前只加载 `maritime`;通过配置项 `ACTIVE_DOMAIN` 指定。
- 不做动态热插拔、领域市场等花哨机制——过度设计,偏离"先跑通"。

## 后果

- 好处:定位有了技术证据。答辩一句话讲清——"内核是通用知识管理引擎,航运是一个可替换的领域包,换包即换行业"。
- 好处:标签/提示词/模板集中一处,改航运知识不碰内核,符合 locality。
- 代价:一次性的归拢重构,有回归风险,靠测试兜底。
- 取代:无(首次确立)。
