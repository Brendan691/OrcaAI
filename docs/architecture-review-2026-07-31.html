Problem

两条 route 复制完整流程，纯文本解析丢失页码、图片、表格和媒体关联，双库写入也没有一致性。

Solution

一个 deep module 接收标准知识条目；解析 adapter 输出 Markdown、资产和 locator，再统一切片与写库。

Wins

  • locality: 入库错误集中
  • leverage: 所有来源复用
  • interface 成为测试面
符合 ADR-0004；需要新增“结构化知识条目”领域词，并决定 Docling 云/本地成本。

2. 合并检索上下文与引用 module

Problem

回答和来源分别拼装，模型没有稳定引用标记；本地切片缺少行号/页码，Web 来源被丢弃。

Solution

本地与 Web 检索统一成 citation-bearing retrieval；上下文与来源由同一 module 生成。

Wins

  • 引用与证据同源
  • locality: 编排集中
  • 角标可点击回溯
强化 CONTEXT 不变量 3，不改变 ADR-0006 的“先召回、后融合排序”。

  classDef deep fill:#0f172a,color:#fff,stroke:#0f172a,stroke-width:3px;
  class G deep

Problem

HTML 正则不稳定且质量不可控；所有错误都变成空结果，调用者无法降级或告知用户。

Solution

一个 deep gateway 负责重试、去重、质量过滤和错误语义，两个真实 adapter 形成可替换 seam。

Wins

  • Provider 可替换
  • 失败不再静默
  • 测试命中一个 interface
选择：SearXNG 免费私有但需要 Docker；托管搜索稳定省事但需要 Key/费用；Bing 只能保留为降级 adapter。

4. 长任务后台化

Speculative ports & adapters

api/files.py · new ingestion job module · web/src/app/documents/page.tsx

HTTP upload waits for parse → tag → embed → two writes

timeout loses progress and error stage

Upload → job ID
↓
queued → parsing → indexing → ready / failed

Problem

OCR、视觉理解、音频转写会让同步上传 interface 超时。

Solution

先用 SQLite job queue 深化任务 module，不立即引入 Redis/Celery。

Wins

  • 进度与失败可见
  • 重试集中在 module
  • 未来可换 worker adapter

Top Recommendation

先合并检索上下文与引用 module

它直接修复联网开关与角标回溯，并给随后所有解析 adapter 提供统一 locator 目标；然后深化入库 module，最后接入选定的搜索与多模态 adapter。
